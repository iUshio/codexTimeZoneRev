# 0.2.3：Windows 内置兼容启动修复

Windows 更新后，部分环境通过普通进程创建方式启动 Store 版 Codex 会返回“拒绝访问（错误 5）”。此版本将包身份兼容引导整合到原 EXE：解压完整 Windows ZIP，双击 `codex_timezone.exe` 即可，无需另外运行 CMD 或 PowerShell 脚本。

## 使用与升级

1. 将完整 ZIP 解压到可写目录，保留 EXE、DLL 和 `data` 资源。
2. 运行 `codex_timezone.exe`，选择需要的时区。首次显示窗口通常需要数秒。
3. 升级已有目录时先退出时区启动器；保留 `data/settings.json`。无需关闭正在使用的 Codex。
4. 新时区仅对新启动的客户端生效。正在运行的客户端会受到重复启动保护，不会被强制关闭。

此版本以 0.2.2 为基线，保留手动账号用量查询和 120 个常用地区时区。

## 修复内容

- 重新发现当前注册的 Store 包，隐藏运行系统自带的包身份引导，核对包版本及应用身份后进入原界面。
- 内部交接失败或超时停止重试；不自动提权、不修改 ACL、不终止已有客户端。
- 避免使用本机出现初始化失败的 PowerShell `-WindowStyle Hidden` 参数，通过 Win32 隐藏辅助窗口。
- 增加 `--verify-launch` 无界面检查及 `context.log`、`context-check.json`、`context-bootstrap/` 引导诊断。
- 启动条件检查单独写入 `preflight.log`，保留真实启动的 `launch.log`。
- 增加参数转义、包身份判断和日志保留测试，修正已有页面测试写死日期的问题。
- 账号用量的重置时间默认选择“本地时间”，按本地系统时区显示；仍可手动切换到“节点时间”，切换不会重新查询账号。

## 检查与问题反馈

在启动器目录运行 `./codex_timezone.exe --verify-launch`。退出码 0 且 `data/context-check.json` 中 `healthy` 为 `true` 表示启动条件检查通过。该检查仅创建、校验并清理挂起的客户端，不执行客户端代码。

系统或 Store 更新后建议先执行此检查。两台工作电脑错开更新时间；再次失败时保留启动器日志和系统、客户端版本。错误 5 本身不能证明 ACL 损坏，请勿批量接管或重置 WindowsApps 权限。

测试覆盖原生后端、界面组件、引导参数及身份契约、隔离模拟客户端和本机安装包挂起检查。为保留正在运行的 Codex，会话中未执行全新真实客户端的窗口和最终时区验收；第二台电脑尚需实际验证。发布包不包含本机设置、账号数据或诊断日志。

本机及另一台电脑在系统更新后出现同类故障的报告支持更新相关的兼容性回归判断，但未通过卸载补丁做因果对照，不能断言具体 KB 是唯一原因。

兼容引导使用微软的 [Invoke-CommandInDesktopPackage](https://learn.microsoft.com/en-us/powershell/module/appx/invoke-commandindesktoppackage) 调试接口。微软保证包身份和虚拟资源访问，但不保证它与正式应用激活的所有行为等同，未来版本仍需复检。
